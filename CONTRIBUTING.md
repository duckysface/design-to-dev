# Contributing

Thanks for your interest in design-to-dev! This document explains how to propose changes.

## Ground rules

The project is a **safety-critical** skill: it moves and deletes files (in a copy), rewrites paths,
and removes AI traces. Every change must preserve these invariants:

- the source folder is never modified;
- nothing is deleted while still referenced (unless merged via `replaced_by`);
- every automatic removal in `ai_traces.py` must be covered by the proof mechanism
  (the file is left untouched if anything unexpected differs);
- no telemetry, no network access except the documented, opt-in `--online` audit and the
  consent-gated security-kit download;
- Python scripts stay **standard library only** (Python 3.9+); the CLI stays **dependency-free**
  (Node 18+).

## Setting up

```sh
git clone https://github.com/duckysface/design-to-dev
cd design-to-dev
npm test        # runs the CLI version check + the three Python test suites
```

No build step, no dependencies to install.

## Running the tests

```sh
npm test                          # everything
python tests/test_pipeline.py     # foundations, deps audit, security kit, AI traces, dedupe
python tests/test_memory.py       # shared memory and hooks
python tests/test_project.py      # project detection
```

Tests never touch the network: OSV.dev, npm and codeload.github.com are simulated locally.
Please add tests for any behavior change — especially new removal patterns in `ai_traces.py`
(both "it is removed" and "it is preserved" cases).

## Making a change

1. Fork and create a branch (`feat/...` or `fix/...`).
2. Keep the bilingual docs in sync: `README.md` (English) and `README.fr.md` (French).
   Detailed reference lives in `docs/commands.md`; behavior of the agent workflow lives in `SKILL.md`.
3. Follow the existing code style: compact, commented in French for rationale (matching the
   codebase), no dead code.
4. Update `CHANGELOG.md` under an `Unreleased` heading.
5. Make sure `npm test` passes on your change, then open a PR.

## Adding an AI tool signature

The tool list lives in the `AI` regex in `scripts/ai_traces.py` (and `references/` where relevant).
When adding a name:

- prefer distinctive names to avoid false positives (`trae.ai` rather than a bare `tra` prefix);
- add a test fixture proving it is caught in a "Generated by …" context and **not** caught
  in legitimate prose/code.

## Reporting security issues

Do **not** open a public issue. See [SECURITY.md](SECURITY.md) for private reporting.
