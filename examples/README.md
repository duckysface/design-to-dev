# Exemple de bout en bout / End-to-end example

Ce dossier montre un export de design désordonné **synthétique** (`messy-export/`) et comment
design-to-dev le transforme. Rejouez chaque étape vous-même — tout est en lecture seule tant que
vous n'appliquez pas le plan.

*This is a fully synthetic walkthrough: a messy design export and the exact commands that tidy it up.
Everything is read-only until you apply the plan.*

## Avant / Before

```
messy-export/
├── .DS_Store                        ← déchet système / OS junk
├── Button.jsx                       ← composant utilisé par screen1
├── Button (copy).jsx                ← doublon exact, utilisé par screen2
├── README.md                        ← contient des traces d'IA
├── screen1.html                     ← badge, meta generator, script injecté
├── screen2.html
├── styles.css                       ← tokens, source de vérité
├── tokens-old.css                   ← ancienne palette (backup-copy)
└── uploads/
    └── pasted-1792877667710-0.png   ← capture collée, orpheline
```

## 1. Inventaire / Inventory

```sh
python ../../scripts/organize.py inventory messy-export
```

Signaux détectés : `duplicate` (Button.jsx ↔ Button (copy).jsx), `os-junk` (.DS_Store),
`backup-copy` (tokens-old.css), `pasted` + `orphan` (la capture dans uploads/).

## 2. Doublons / Duplicates

```sh
python ../../scripts/organize.py dedupe messy-export
```

```
doublons exacts — canonique : Button.jsx
  => Button (copy).jsx  (référencé par screen2.html → fusion proposée)
```

Le doublon est **référencé par screen2.html** : il ne peut pas être simplement supprimé.
La fusion proposée (`delete` + `replaced_by: Button.jsx`) réécrit la référence dans screen2.html
au moment de l'application. `plan-check` refuse toute suppression de doublon référencé sans
`replaced_by` — et tout quasi-doublon sans `replaced_by` ni `review`.

## 3. Traces d'IA / AI traces

```sh
python ../../scripts/ai_traces.py clean messy-export --dry-run
```

7 traces retirables, 0 à vérifier : commentaire « Generated by v0 » (×2), `<meta name="generator">`,
badge « Edit with Lovable », script `gptengineer.js`, ligne « This project was built with… » et
section « ## Build with Lovable ». Le design est prouvé identique avant/après, sinon le fichier
n'est pas touché.

## 4. Plan et application / Plan and apply

`plan.json` (fourni ici) déplace chaque fichier à sa place et fusionne le doublon :

```sh
python ../../scripts/organize.py plan-check plan.json
python ../../scripts/organize.py apply plan.json            # aperçu : l'arbre cible
python ../../scripts/organize.py apply plan.json --apply    # nécessite une cible vide
python ../../scripts/organize.py verify messy-export-clean
```

## Après / After

```
messy-export-clean/
├── prototypes/
│   ├── screen1.html                 ← src="./Button.jsx" réécrit en ../src/components/Button.jsx
│   └── screen2.html                 ← idem : la fusion a redirigé la référence
├── src/
│   ├── components/Button.jsx        ← copie canonique (unique)
│   └── styles/styles.css
├── docs/
│   ├── design-system/README.md
│   └── cleanup/                     ← report.md + file-map.json (avant → après)
└── README.md
```

La source `messy-export/` n'est jamais modifiée — le retour arrière consiste à supprimer la cible.
